# 认知卸载：把执行交出去，把判断练起来

彭罗健 · 2026-10-12 · 实践记录

在一次论文改稿中，我逐渐意识到，Agent 的价值不能只用它替我写了多少段话、画了多少图来衡量。更重要的是，它能否让我有精力从导师的视角看整篇论文：问题值得研究吗？相对前作新增了什么？证据撑得住主张吗？主线应该怎样组织？

我把两种使用方式区分为“认知卸载”和“认知投降”。前者让 Agent 分担阅读整理、计算、绘图和初稿，研究者保留判断与责任；后者把任务一股脑交出去，不检查依据就接受答案。这是我在这里采用的实践区分，不是经过实验验证的心理学分类。

## 五个有效的动作

1. 划清材料与条件的边界。已有数据能做什么、哪些条件不能改变、哪些工作需要新增实验，要先交代。
2. 解释跑偏时补材料。实验室前作、方法原文和实验记录，比反复争论一个脱离背景的解释更有用。
3. 先看产物，再替换。图表预览、文字差异与副本，给人留下具体检查的机会。
4. 追问为什么做这个。额外的图或分析要服务于某个判断；不能把忙碌当成进展。
5. 独立复核。图、表和正文都要核对；换一个 Agent 可以补充视角，但最终仍需回到数据、字段、脚本与来源。

这些动作也有边界。补文献不会消灭所有错误，第二个模型也会错，固定的主线不能压过新的证据。非核心公式可以分担给 Agent；公式本身若是贡献，就需要研究者深入理解和检验。

## 提问的目的，是让工作推进

一个有用的 Agent 先读材料，再指出最关键的缺口，每轮问一个能改变下一步的问题。用户答不上来时，它应提供有依据的候选路径，而不是把整个任务退回去。材料与目标已经清楚时，就开始执行，不应无限访谈。

不同模型在不同任务上的边界，需要通过实际协作认识。遇到失败，要区分是缺背景、缺数据、计算错误、工具事故，还是研究方向本来就有分歧。熟悉这些差异，才能更有效地安排工作。

我希望这个过程既提高交付能力，也训练判断能力：用节省下来的执行时间，解释清楚研究为什么这样做。
