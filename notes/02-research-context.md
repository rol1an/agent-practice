# 文件树：把组里的知识变成可用的上下文

彭罗健 · 2026-10-12 · 实践记录

目录的价值不是整齐，而是一个新加入的人或 Agent 能找到研究从哪里来、现在做到哪里、哪些决定不能凭空猜。

在实际改稿中，我是遇到错误后才逐步补进前作、方法原文、原始数据、字段说明和导师讨论记录。这个树是工作需要和错误逼出来的，不是一开始就设计好的。

## 三种容易混在一起的东西

- 材料：原稿、论文、实验记录、数据、脚本。
- 对材料的理解：背景卡、文献关系、结果摘要。
- 已经作出的决定：采用哪个解释、哪些分析先做、什么需要老师判断。

三者要能互相追溯，也要保留区别。Agent 的总结不是原文；会议里的建议不是已经确认的方向；文件名带 final 也不意味着它就是当前稿。

## 从个人经验到组内贡献

一次操作经验可以留下输入材料、参数、步骤、验收判据、例外和适用边界。导师讲过的操作整理成 SOP 后，仍需实验人员确认；只有验证过的内容才适合推广。

从具体任务进入学习，遇到问题时借助 Agent 找到知识入口，再回到经典文献或实验核实。重复出现的基础概念仍值得系统学习，完成任务不等于已经掌握。

对组里的贡献可以很具体：一张有来源的文献地图、一条能追查结果的分析链、一份带适用边界的操作规范。这样，人员更替后，后来者仍然能从已有经验继续做，而不是每次从头摸索。
