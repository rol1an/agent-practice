# 材料索引与交接约定

以下是按需选用的字段，不要求用户补齐所有字段再开始。

## 文件记录

每份关键材料有稳定 ID，例如 `paper-001`、`data-001`。建议记录：

- `path`：相对项目路径；外部路径单独标记，不冒充可移植。
- `kind`：稿件、审稿意见、期刊文献、预印本、数据、脚本、会议记录、结果等。
- `source`：来源文件/DOI/公开链接/用户提供；无法确认就留空并记录问题。
- `read_status`：未读、已读部分、已读全文、无法读取。已下载不等于已读。
- `version_status`：历史、候选当前、用户确认当前、待确认。
- `basis`：版本或作者归属的确认依据。
- `sha256`：按需计算，仅用于字节一致性。
- `relations`：派生自、引用、取代、用于生成等关系。

示例为合成数据，不对应真实项目：

```json
{
  "id": "result-001",
  "path": "analysis/run-01/results.json",
  "kind": "derived_result",
  "read_status": "read",
  "version_status": "candidate",
  "relations": [
    {"type": "input", "id": "data-001"},
    {"type": "generated_by", "id": "script-001"},
    {"type": "configured_by", "id": "config-001"}
  ],
  "open_questions": ["正文引用的是此轮结果还是上一轮结果？"]
}
```

## 背景与决定

把“前作已知”“本轮问题”“实验条件”“不能补做的事”分开。导师原话或会议转写保留来源；整理后的 SOP 是衍生产物。会议建议、用户理解、已确认决定、Agent 推断分别标明，不能混写为导师决定。

决定记录应包含：问题、候选项、采用项、依据、决定者（未知则不填）、日期（未知则不猜）、影响文件。后续改变主张时保留旧决定和改变原因，不静默覆盖历史。

## 缺件与追溯

缺件条目写“缺什么 → 阻碍哪个判断 → 谁/哪里可能提供 → 可否先做其他工作”。没有全文、没有动物编号、没有仪器校准信息，造成的限制不同。禁止填造记录。

对每个关键数字，尽可能关联输入数据、样本/分组定义、字段、单位、排除规则、脚本版本、配置、输出位置、正文/图表引用位置。索引暂时不全可以交付，但必须标明未确认的边。

## 交接验收

接手者能找到当前稿与其确认依据、打开关键来源、区分原始和派生文件、追查一个结果的计算路径、知道还有哪些材料或判断未定。是否成功重跑分析单独报告，不把静态路径检查说成可复现验证。
